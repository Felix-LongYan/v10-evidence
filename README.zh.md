# V10 evidence

## 这个仓库是什么

这是一个用于申请材料核验的现有策略游戏原型、规则测试床和历史运行证据仓库，提供无需 API 的本地约束检验入口。

## 每个文件是什么、证明什么

以下复制件保持原始内容；本次整理不新增实验，不修改原有实验结论。

- `src/caocao_deepseek.py`：V10 原版源码，是本次四项检验的原版对象；保留其原有行为。
- `src/caocao_deepseek_v11.py`：由随附的 `tools/v10_patch.py` 从上述原版生成的补丁版，是同一组检验的对照对象。生成时只在运行中的内存里将补丁脚本的 `SRC` 指向仓库复制件，并用 `--out` 指定此文件；未修改补丁脚本或原版文件内容。
- `src/demo_script.py`：原演示辅助脚本，保存演示流程的实现；不作为演示成功的独立证据，不由离线入口执行。
- `src/requirements.txt`：原程序依赖声明，原样保留。它没有锁定完整依赖版本；下面的离线命令只需 Python 标准库，无需安装这些依赖。
- `tools/v10_patch.py`：原补丁生成脚本，记录补丁如何生成；它默认仍指向原作者桌面的旧路径，不能直接按默认参数在其他机器上运行。已生成的补丁版随仓库提供。
- `tools/constraint_demo.py`：原约束检验脚本。离线入口以 `--both --path <仓库>/src` 调用它，对两版执行相同的四项检查：数值变化是否限制在 ±12、是否拒绝字符串 `"false"` 触发事件、非法数值是否留下半更新、是否记录越界。第四项是日志仪器能力。
- `evidence/demo_run.log`：已有演示的输出日志，77 行；支持核对当时记录的输出，不能据此重建原始 API 响应。
- `evidence/constraint_demo.log`：已有原版约束演示日志，保留当时的三项演示记录；与本次新生成的四项对照日志分开保存。
- `evidence/constraint_verify.log`：运行 `reproduce.sh` 时生成或覆盖的四项对照输出，包含实际检验结果及总分：原版 0/4、补丁版 4/4。
- `evidence/timeleak-runs/run_*.txt`：已有时代泄露候选扫描所用的运行文本。
- `evidence/timeleak-runs/hits.csv`：已有关键词候选命中表；候选扫描结果不能证明不存在时代泄露。
- `evidence/timeleak-runs/results.md`：该批扫描的原有汇总、方法和边界，原样保留；不是新的人工复核结论。
- `testbed/env.py`：规则环境、样本生成和 oracle 实现，可检查标准答案如何由规则算出；不构成独立第三方正确性验证。
- `testbed/ask.py`：原模型提问、评分和落盘脚本，可检查既有实验的实现。默认运行会请求 API，离线入口不执行它。
- `testbed/runs/*/results.csv`：各历史运行的逐条记录；`run-20261015-1607/results.csv` 是本次核对的主运行文件，541 行含表头，对应 540 条数据记录。其他历史运行也完整保留，离线入口分别打印其实际行数，不把它们合并计为主运行。
- `testbed/runs/*/summary.md`：相应历史运行的原始汇总；保留其各自口径，不把文件存在或行数通过解释成重新验证了全部指标。
- `testbed/runs/.DS_Store`：随原目录复制的 Finder 元数据，无实验含义。
- `tools/compare_runs.py`：逐题比对两次历史运行；定义一道题的六个字段（kind、clauses、state、action、intervention、oracle answer）须 180 题全部一致，并分别打印两次运行在 normal 与 ood 两组的准确率。仅用标准库。
- `reproduce.sh`：新增的离线核验入口，检查两版语法，运行原约束脚本，保存输出并核对上述行数。包装层只收集检验脚本实际返回的四个布尔结果来计算总分；缺项、异常或验收不符都会以非零状态退出，不预填检验结果。
- `README.md`：本整理说明、文件用途与证据边界。

复制来源：`src/` 的三个原始文件、两份已有日志和 `evidence/timeleak-runs/` 来自 `~/Desktop/面试的项目/`；`tools/` 的两个脚本及 `testbed/` 内容来自 `~/Documents/deepseek-harness/default-workspace/`。两份已有日志仅在复制时改名为 `demo_run.log` 和 `constraint_demo.log`，源文件未改名或移动。

## 怎么复现

macOS 上需已安装 Python 3.12 或更新版本。在本仓库目录打开终端，执行一条命令：

```sh
./reproduce.sh
```

命令依次显示两版语法检查、四项约束逐项对照及原版 0/4 / 补丁版 4/4、各历史 CSV 行数（主运行为 541，含表头）、演示日志行数（77）。约束输出写入 `evidence/constraint_verify.log`，再次执行会覆盖此核验日志。

不需要 API key、联网或安装 SDK。原程序顶层导入 `openai`，离线入口在当前 Python 进程中提供仅满足导入的占位模块；任何 API 客户端构造或 socket 网络操作都会报错退出。四项检查只执行原程序的本地状态、事件和日志函数，不使用模型响应。语法检查不运行两版程序的主入口，也不生成字节码缓存。

此命令复现的是本地四项行为检查，并核对历史文件的行数；它不会重新运行历史模型实验、演示或时代泄露扫描。行数核对只能检查文件规模，不证明内容真实性或指标正确性。

## 这个证据不能证明什么

- **单模型**：历史材料仅涉及已有模型配置，没有跨模型对照，不能推广为所有 LLM 的能力结论。
- **无固定快照**：未固定模型服务快照，依赖声明也未完整锁定；无法保证其他时间的服务返回相同结果，温度为 0 也不等于逐次输出完全相同。
- **oracle 与规则同一作者**：oracle 就是同一作者实现的规则函数，缺少第三方独立实现交叉验证，不能据此证明真实世界的因果有效性或一般因果推理能力。
- **原始 API 响应未留存**：没有完整原始 API 响应与请求元数据。CSV 中的 `raw_response` 是脚本截断保存的文本片段，演示日志也是处理后的输出，不能据此还原完整响应、用量或服务端版本。
- **检验范围有限**：0/4 和 4/4 只对应这四个具体检验输入；不能证明所有边界输入都正确、程序没有其他缺陷，或模型能力因补丁而提高。
- **历史记录与重新运行不同**：保留 CSV、汇总和日志不等于离线重跑了付费模型实验；关键词候选扫描也不能证明时代泄露风险为零。
